# SergD_max-lead-bot

Лидогенерирующий бот в мессенджере **MAX** (max.ru) для форума «Педагоги России».
Собран на Python 3.10+ **за 3 часа** — от чистого листа до продакшен-деплоя к мероприятию с 2000 участников.

---

## 📖 Кейс

Елена Маслакова — «Большие пряничники Урала», 6 лет производства, поставки школам.
Участвует в форуме «Педагоги России» как эксперт: стойка + мастер-класс, аудитория — директора и завучи школ.

**Задача**: 2000 посетителей форума → собрать у себя в канале в MAX, с контактами для дальнейшей работы.
**Ограничения**: мероприятие через 2 дня, канал в MAX (не Telegram) — готовых решений мало.

**Что сделано**:
- QR-код на стойке → deep-link на бота
- Три ветки сценария под разные профили посетителя
- Анкета ФИО/город/школа/телефон (телефон — одним тапом через `request_contact`)
- Промокод/PDF-методичка/договор о партнёрстве → прямо в чат
- Уведомления админам о каждом новом лиде
- Ежедневный дайджест в 08:00 Екатеринбурга
- Согласие на обработку ПДн (152-ФЗ) + право на удаление

## 🛠 Стек

- **Python 3.10+**, asyncio, long-polling (без вебхуков → без домена/SSL)
- **[maxapi](https://github.com/love-apples/maxapi)** — Python-клиент для MAX Bot API (aiogram-like)
- **SQLite** (`aiosqlite`) + WAL-mode для конкурентной записи
- **ReportLab** — генерация PDF-плейсхолдеров с кириллицей
- **systemd** — запуск на Oracle ARM-сервере в Москве
- **zoneinfo** — таймзона для дайджеста (Екатеринбург, UTC+5)

## ✨ Фичи, которые оказались важными

### 🔘 `request_contact` одним тапом
В MAX есть нативная кнопка «Поделиться контактом» — номер телефона подтягивается из профиля автоматически. На мероприятии, где директор стоит в очереди к стойке, это разница между «ввёл» и «не ввёл» — ⅔ людей не хотят вручную печатать номер.

### 📋 `clipboard`-кнопка
Скрипт для разговора с директором («На форуме я встретила "Больших пряничников"…») уезжает в буфер обмена посетителя по тапу. Ничего не надо выделять — сразу можно вставить в мессенджер директора.

### 🛡 Админка без костылей
`/admin <secret>` мы [выпилили как уязвимый](#безопасность). Админы задаются в `ADMIN_USER_IDS` на старте — засеваются в БД автоматически. В личку каждому приходит:

```
🆕 Новая анкета в боте!
🎁 Скидка (А)
👤 Иванова Анна Петровна
🏙 Пермь
🏫 Школа 7
📞 +79991112233
```

И ежедневно в 08:00 Екб — дайджест за вчера:

```
📊 Дайджест за вчера (Asia/Yekaterinburg)
👥 Всего новых: 47
  🎁 Скидка (А): 31
  💰 Партнёрство (Б): 9
  📖 Идеи (В): 7
Контакты:
• [A] Иванова Анна Петровна — Пермь — Школа 7 — +79991112233
...
```

### 🔒 152-ФЗ из коробки
- Согласие на обработку ПДн зашито в первую строку формы
- Команда «удалить мои данные» — регулярка ловит варианты фраз, бот удаляет все записи пользователя
- Защита от CSV-injection в экспорте (`=+-@` → префикс `'`)
- Markdown-escape в ответах, где рендерится имя пользователя

### 🏗 Устойчивость к нагрузке
- SQLite в WAL-mode + `busy_timeout=5000`
- Проверено 50 параллельных записей одновременно — 0 блокировок
- Fire-and-forget задачи (уведомления админам) логируют исключения, а не молча теряют
- Ежечасные `sqlite3 .backup` (не rsync — чтобы не поймать половину транзакции)

## 🔐 Безопасность

Перед выпуском бот прошёл security-review тремя агентами — [что было поправлено](deploy.md#чек-лист-перед-форумом):

- `/admin <secret>` удалён — админы только через `ADMIN_USER_IDS`
- Токен в `.env.example` заменён на плейсхолдер
- CSV-инъекция: все ячейки с `=+-@` префиксуются апострофом
- Markdown-спуф: имя пользователя escape-ится перед отправкой с `format=MARKDOWN`
- DEBUG-логи не пишут SQL с параметрами (`aiosqlite/aiohttp/asyncio` принудительно на INFO)
- `.env` на сервере — `chmod 600`, systemd с `ProtectSystem=strict`
- Бэкап БД через `sqlite3 .backup`, не rsync
